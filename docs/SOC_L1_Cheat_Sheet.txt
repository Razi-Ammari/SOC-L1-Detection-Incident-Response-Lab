1. IMPORTANT WINDOWS SECURITY EVENT IDS
==================================================

4624 - Successful Logon
Use Case: Detect successful authentication.

4625 - Failed Logon
Use Case: Detect brute-force attempts and failed authentication.

4634 - Logoff
Use Case: Track user logoff activity.

4688 - Process Creation
Use Case: Detect process execution from Windows Security logs.

4720 - User Account Created
Use Case: Detect new local/domain account creation.

4726 - User Account Deleted
Use Case: Detect account deletion.

4732 - User Added to Group
Use Case: Detect privilege changes.

1102 - Log Cleared
Use Case: Detect possible anti-forensic behavior.

4104 - PowerShell Script Block Logging
Use Case: Detect PowerShell script execution.

7045 - Service Installed
Use Case: Detect persistence through service creation.

==================================================

Sysmon Event ID 1 - Process Creation
Use Case: Detect executed processes, command line, parent process and user.

Sysmon Event ID 3 - Network Connection
Use Case: Detect network activity, source IP, destination IP and destination port.

Sysmon Event ID 7 - Image Loaded
Use Case: Detect DLL or library loading.

Sysmon Event ID 11 - FileCreate
Use Case: Detect file creation.

Sysmon Event ID 13 - Registry Value Set
Use Case: Detect registry modification.

Sysmon Event ID 22 - DNS Query
Use Case: Detect DNS activity.

Sysmon Event ID 23 - File Deleted
Use Case: Detect deleted files.

Sysmon Event ID 25 - Process Tampering
Use Case: Detect possible injection or tampering.

3. COMMON SPLUNK SEARCHES
==================================================

All Windows Security Events:
index=windows

Failed Logons:
index=windows "<EventID>4625</EventID>"

Successful Logons:
index=windows "<EventID>4624</EventID>"

Sysmon Process Creation:
index=sysmon "<EventID>1</EventID>"

Sysmon Network Connections:
index=sysmon "<EventID>3</EventID>"

PowerShell Activity:
index=sysmon "<EventID>1</EventID>" "powershell.exe"

Encoded PowerShell Command:
index=sysmon "<EventID>1</EventID>" "EncodedCommand"

Execution Policy Bypass:
index=sysmon "<EventID>1</EventID>" "ExecutionPolicy Bypass"

Suspicious DownloadString:
index=sysmon "<EventID>1</EventID>" "DownloadString"

Top Source IPs for Failed Logons:
index=windows "<EventID>4625</EventID>"
| rex "<Data Name='IpAddress'>(?<src_ip>[^<]+)</Data>"
| stats count by src_ip
| sort - count

==================================================
4. USEFUL SPLUNK COMMANDS
==================================================

rex:
Used to extract fields from raw XML logs.

Example:
| rex "<Data Name='IpAddress'>(?<src_ip>[^<]+)</Data>"

stats:
Used to count and summarize events.

Example:
| stats count by src_ip user host

values():
Used to show unique values observed in events.

Example:
| stats values(Image) as involved_processes by host

eval:
Used to create a new calculated field.

case():
Used to classify events depending on conditions.

table:
Used to display only the useful columns.

sort:
Used to sort results.

earliest:
Used to limit search by time.

Example:
earliest=-48h

7. IOC VS IOA
==================================================

IOC - Indicator of Compromise:
Evidence that a compromise may have occurred.

Examples:
- IP address
- Domain
- URL
- File hash
- Malware name
- Suspicious file path

IOA - Indicator of Attack:
Evidence that an attack behavior is happening.

Examples:
- Multiple failed logons
- Encoded PowerShell execution
- Suspicious process tree
- Unusual network connection
- ExecutionPolicy Bypass
- DownloadString usage

==================================================
9. FALSE POSITIVE VS TRUE POSITIVE
==================================================

True Positive:
- Malicious or suspicious activity confirmed.
- Real attacker behavior or lab attack pattern observed.
- Requires investigation or response.

False Positive:
- Benign activity.
- Legitimate process or user action.
- Alert can be closed after verification.

10. SOC L1 INVESTIGATION CHECKLIST
==================================================

1. Validate the alert.
2. Check alert rule and conditions.
3. Identify source IP and reputation.
4. Identify user and hostname.
5. Check Event ID and description.
6. Review command line.
7. Check parent and child processes.
8. Build a timeline around the alert.
9. Correlate with Sysmon logs.
10. Collect evidence and screenshots.
11. Determine severity.
12. Close alert or escalate to SOC L2.
13. Document all findings.

13. COMMON THREAT PATTERNS
==================================================

Brute Force:
Multiple failed logons from the same IP or multiple IPs.

PowerShell Abuse:
Encoded commands, downloads, script execution.

Suspicious Download:
Files downloaded from external or unknown sources.

Persistence:
Registry run keys, scheduled tasks, new services.

Log Clearing:
Event logs cleared to hide activity.

Privilege Escalation:
User added to admin groups or token manipulation.
